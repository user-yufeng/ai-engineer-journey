工具系统深挖与 MCP

Lesson 2 · 第 1 周 · 约 100 分钟 · 绑定 Mission

这课结束时，你会拿到

  • 判断力：什么时候写函数工具、什么时候写类工具，不再纠结
  • 一个能用 Tool 类写的、带内部状态的工具
  • agent 成功接上一个 MCP 服务器——你简历上那行「MCP」从此有了实底

先想清楚：函数工具 vs 类工具

第一课你已经用过 @tool。它适合「给一段数据、返回一段结果」的纯函数。一旦你的工具需要记住东西、或者需要先连接再使用，就必须升级成 Tool 类。

判断标准就一条：这个工具有没有「记忆」。查个字典是函数；连数据库、开浏览器、维护一个会话，都是类。

Tool 类的完整骨架

from smolagents import Tool


class ScoreStore(Tool):
    name = "score_store"
    description = "记录并查询学员的练习分数。存过就能查，没存过返回无记录。"
    inputs = {
        "action": {"type": "string", "description": "动作：save 或 get"},
        "name": {"type": "string", "description": "学员姓名"},
        "score": {"type": "integer", "description": "分数，action 为 get 时可随便填", "nullable": True},
    }
    output_type = "string"

    def __init__(self):
        super().__init__()
        self.records = {}          # 这就是类的优势：跨调用的内部状态

    def forward(self, action: str, name: str, score: int | None = None) -> str:
        if action == "save":
            self.records[name] = score
            return f"已记录 {name}: {score}"
        return f"{name}: {self.records.get(name, '无记录')}"

和 @tool 比，多了三样东西：name、结构化的 inputs、以及 forward()——agent 每次调用工具，真正执行的就是 forward。

工具没被 agent 调用时，九成是 description 的问题。它不是写给人看的注释，是模型决定「调不调、怎么传参」的唯一依据。写完自问一句：一个从没见过这个项目的模型，光看这段话知道什么时候该用吗？

MCP：给 agent 装外接工具包

MCP（Model Context Protocol）是一套标准插座：别人把工具包做成一个「MCP 服务器」，任何支持 MCP 的 agent 一插就能用，不用自己写。第一课你见过它的名词解释，现在真的插一个。

先装 MCP 扩展（我已经帮你装好了，你重装环境时才需要跑这条）：

uv add "smolagents[mcp]" "mcp<2"

给 smolagents 加上 MCP 客户端能力。第二条是关键：mcp 这个包 2.x 版本把接口改了，smolagents 1.26 还没跟上，不锁在 1.x 会报 cannot import name 'streamablehttp_client'。我已经在你机器上装好并验证过，你重装环境时才需要跑。

然后新建 mcp_time.py：

import os
from dotenv import load_dotenv
from mcp import StdioServerParameters
from smolagents import CodeAgent, OpenAIServerModel, ToolCollection

load_dotenv()

model = OpenAIServerModel(
    model_id="glm-4-flash",
    api_base="https://open.bigmodel.cn/api/paas/v4",
    api_key=os.environ["ZHIPU_API_KEY"],
)

server_params = StdioServerParameters(command="uvx", args=["mcp-server-time"])

with ToolCollection.from_mcp(server_params, trust_remote_code=True) as tools:
    print("从 MCP 服务器拿到了:", [t.name for t in tools.tools])
    agent = CodeAgent(tools=[*tools.tools], model=model, add_base_tools=False)
    agent.run("现在上海几点？转化成纽约时间。")

跑：

uv run python mcp_time.py

uvx 是 uv 自带的：它会临时下载并运行 mcp-server-time 这个 MCP 服务器，agent 启动时自动连上它、把它的工具全部注册进来。

留意第一行打印——你会看到从服务器拿到的真实工具名列表。这就是「插件」的感觉：你没写一行时间处理代码，能力是插进来的。

trust_remote_code=True 是什么意思：MCP 服务器的代码会在你本机跑。官方默认关闭，是提醒你「别随便信任来路不明的服务器」。mcp-server-time 是官方维护的，放心开。这个意识以后接第三方 MCP 时要有。
