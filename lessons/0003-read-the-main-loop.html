Part A · 今天只做这三步

Step 1 · 加一行代码，数圈数

打开 lab/Score_Store.py，在最后加一行（加在两个 agent.run 的后面）：

print("这轮转了", len(agent.memory.steps), "圈")

agent.memory.steps 是这次运行的全程记录，每转一圈（每想一次）记一条。len() 数它有几条。

然后跑：

uv run python Score_Store.py

预期：打印出 2 或 3 之类的数字（存分那次），和另一个数字（查分那次）。

Step 2 · 对号入座

把你终端里「查分那次 run」的输出截出来，跟下面的表对照——每一行终端输出，都是循环里的一个动作：

终端里你看到的 循环里发生的事
Step 1进入第 1 圈
Executing parsed code:模型想完了，把它写的代码抠出来执行（你的 forward() 在这被调用）
Execution logs: 张三 的分数: 100执行结果写回 memory（下一圈的燃料）
Step 2进入第 2 圈（模型还没交卷，while 继续转）
Final answer: 张三的分数是100。模型调了 final_answer() = 交卷，while 条件不满足，结束

看到规律了吗：「没交卷且没超 20 步 → 喂历史 → 模型想 → 抠代码 → 执行 → 记结果 → 回到开头」。转几圈，终端就打几个 Step。

Step 3 · 亲手炸一次保险丝

打开 lab/gym.py，找到 agent = CodeAgent(...) 这行，在括号里加一个参数：

agent = CodeAgent(tools=[gym_count], model=model, add_base_tools=False, max_steps=1)

max_steps=1：只许转 1 圈。然后跑它。模型答「深圳和广州加起来多少家」至少要两圈，你猜会发生什么？

跑完看报错里有没有 AgentMaxStepsError——那就是循环保险丝炸了。看明白后把这个参数删掉。

今天就到这。三个动作：数圈数、对号入座、炸保险丝。都不用读源码。

Part B · 读源码（另一晚再做，今天跳过）

等你 Part A 做完、终端输出能对上号了，我们再开 agents.py——到时候你不是「读陌生代码」，而是拿着你亲手跑出来的现象去源码里找对应，难度完全不同。预告要找的三处：
